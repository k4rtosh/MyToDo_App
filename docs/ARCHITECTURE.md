## 1. Главное решение

**Остаёмся на SPA в одном HTML-файле** — пока. Причины:

* открывается двойным щелчком, работает оффлайн, не требует сервера, сборки и npm;
* данные в браузере, никаких аккаунтов;
* в песочнице нет доступа к npm-реестру, так что «настоящая» сборка (Vite/React) сейчас всё равно не собралась бы.

**Меняем архитектуру, когда появится хотя бы одно из:**

| Триггер | Что делать |
|---|---|
| Больше ~500–800 задач | виртуализация списка + IndexedDB вместо localStorage |
| Нужна синхронизация между устройствами | бэкенд (Supabase) + офлайн-очередь изменений |
| Нужен доступ с телефона как приложение | PWA (manifest + service worker) или APK-обёртка |
| Файл перевалит за ~3000 строк | разбить на модули + сборка скриптом на Node |

## 2. Слои (уже разделены внутри файла)

1. **Данные и парсер** — `SEED_TEXT`, `normalizeText`, `parseImport`, `detectTags`.
2. **Модель** — `makeProject`, `makeCard`, `makeTask`, `uid` (id с префиксом `p/c/t/s`).
3. **Хранилище** — `load`, `save`, `migrateV1`, ключ `todoAppV2`, поле `version`.
4. **Выборки и статистика** — `projectStats`, `cardStats`, `totalStats`, `visibleTasks`, `allTags`.
5. **Маршрутизация** — hash-роуты: `#/`, `#/p/:id`, `#/p/:id/c/:id`.
6. **Отрисовка** — `renderProjects`, `renderProject`, `renderCard`, `renderHeader`.
7. **Модалки** — `openProjectModal`, `openCardModal`, `openTaskModal`, `openImportModal`, `openConfirm`.
8. **Действия** — сохранение, удаление, импорт, экспорт.
9. **События** — одно делегирование на `document` (`onDocumentClick`).

Правило: слой 6 не меняет данные, слой 8 не трогает DOM напрямую. Это позволяет менять хранение или UI независимо.

## 3. Модель данных

```
project { id, name, note, createdAt }
card    { id, projectId, name, date, createdAt }
task    { id, cardId, title, note, priority, done, subs[], tags[], links[], paths[], createdAt }
sub     { id, text, done, links[], paths[], waiting }
```

* `priority`: `high | normal | low`, выставляется автоматически по словам «срочно/оперативно/asap».
* `waiting` у подпункта — распознаётся по «ожидается/ждём».
* `links` / `paths` вытаскиваются из текста (`e1c://…`, `Z:\…`), в тексте остаются короткие подписи.
* Удаление каскадное: проект → карточки → задачи.
* Миграция: если найден ключ `todoListV1` (ранние версии) или `todoAppV2`, данные переносятся в проект + карточку автоматически.

## 4. UI

Три уровня, везде крошки и кнопка «назад» (работает и системная кнопка браузера):

```
Проекты  →  Карточки проекта  →  Задачи карточки
```

Что уже есть: сетка карточек с прогрессом, поиск и фильтры внутри карточки, теги, чек-листы подпунктов, приоритеты, импорт текста с превью, экспорт/импорт JSON.

**Что добавить в UI (по приоритету):**

1. **Дедлайны** у задач: поле `due`, бейдж «просрочено/сегодня/на неделе», сортировка.
2. **Перемещение задачи** в другую карточку (в модалке — селект «Карточка»).
3. **Массовые действия**: выделить несколько задач → закрыть/удалить/перенести.
4. **Drag&drop** порядка внутри карточки (поле `order`).
5. **Глобальный поиск** по всем проектам и карточкам (кнопка в шапке).
6. **Клавиатура**: `n` — новая задача, `/` — поиск, `Esc` — закрыть модалку, `Enter` — сохранить; фокус-ловушка в модалках.
7. **Сворачивание подпунктов по умолчанию** для длинных задач (уже есть ручное).

## 6. Что оптимизировать

* **Запись в localStorage** — ✅ дебаунс 250 мс + принудительный `flushSave` при закрытии вкладки.
* **Поиск** — ✅ дебаунс 140 мс в глобальном поиске; поиск внутри карточки перерисовывает только список.
* **`innerHTML`** — ✅ точечное обновление одной задачи (`patchTask`) для чекбоксов; полная перерисовка — только когда меняется состав списка.
* **Статистика** — ✅ мемоизация по `cardId`/`projectId` и сброс кэша при изменениях (`clearStats`).
* **localStorage лимит ~5 МБ** — ⏳ при росте перейти на IndexedDB (там же хранить вложения).
* **Импорт больших файлов** — ⏳ разбирать чанками, показывать прогресс.

## 7. Как перейти на модули без npm

```
src/
  store.js      // состояние, load/save, миграции
  domain.js     // модели, парсер, теги
  selectors.js  // выборки и статистика
  router.js     // hash-роуты
  views/        // экраны
  components/   // task-card, chips, modal
build.js        // Node: склеивает модули в один dist/app.html
```

`build.js` на 40 строк решает задачу без зависимостей: читает файлы, вырезает `import/export`, подставляет в шаблон. Так сохраняется главное свойство — **один файл, который открывается офлайн**.

## 8. Риски

* **Данные живут в браузере.** Чистка кэша, другой браузер, режим инкогнито — и задач нет. Поэтому в шапке есть экспорт `⤓`: делать его раз в день/после импорта.
* **`file://`** — ES-модули и service worker там не работают. Отсюда и один файл.
* **Рост файла** — при 3000+ строк править станет тяжело, тогда пора на шаги из п. 7.
* **Дубли задач** — повторный импорт того же файла создаст копии; в v2.1 добавить дедупликацию по названию+подпунктам.

## 9. Drag & drop: план

**Что перетаскиваем** — два уровня (уточняем, какой нужен первым):

1. **Задачи внутри карточки** — основной сценарий: выстроить порядок работ.
2. **Карточки внутри проекта** — порядок списков по датам.

**Модель.** У задач и карточек есть `position` (`double precision`). Вставка между соседями: `(prev + next) / 2`. Когда зазор схлопывается (< 0.0001) — перенумерация всех элементов (`1000, 2000, 3000…`). Тот же приём уже заложен в схеме Supabase.

**Сортировка.** В списке сортировок появляется режим «Вручную», и перетаскивание доступно **только в нём** — иначе пользователь тащит задачу, а список тут же пересортировывается по приоритету (классическая UX-ловушка).

**Реализация без библиотек.**

* Pointer Events: `pointerdown` на ручке `⋮⋮` → `setPointerCapture` → `pointermove` → `pointerup`.
* Тащим за ручку, а не за всю карточку: иначе на телефоне невозможно листать список.
* Плейсхолдер — пунктирная полоса на месте будущей вставки; перетаскиваемый элемент полупрозрачный.
* Автопрокрутка у краёв экрана (зона 60px, `requestAnimationFrame`).
* После отпускания — пересчёт `position` у затронутых элементов и `scheduleSave()`.

**Доступность (обязательно).**

* Клавиатура: `Alt+↑/↓` на задаче — сдвиг на позицию, объявление через `aria-live` («Перемещено на 3 из 7»).
* Ручка — это `<button aria-label="Перетащить">`, доступная с клавиатуры.

**Ограничения.**

* При активном поиске/фильтре перетаскивание выключается: непонятно, куда вставлять в отфильтрованном списке.
* `touch-action: none` только на ручке, не на всём списке.
* Два устройства переставили одновременно — last-write-wins по `position`, данные не ломаются.

**Оценка.** Задачи — ~120 строк кода + тесты; карточки — переиспользование, ещё ~40 строк.
